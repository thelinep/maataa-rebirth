# Drive Project Catalog and Consolidation Decisions

**Inventory date:** 2026-10-07
**Catalog home:** this MAATAA UI workspace, `docs/knowledge-graph/`
**Purpose:** one navigable inventory of project families and their current locations, followed by a safe consolidation decision. This is a catalog, not a claim that every source is current or releasable.

## Decision

Keep source projects in their existing repositories for now. Make this catalog the shared index, then consolidate only after each family has one selected source of truth and a preservation plan. Do not bulk-copy or delete projects: the internal drive reports about **10 GiB free**, several repositories have local changes, and many Downloads are snapshots or generated packs rather than independent products.

“One place” for now means one portfolio map, not one giant repository. Keep product repositories, release evidence, snapshots, and data collections separate. Use links to the canonical folders rather than duplicating their contents.

- **Preserve, do not consolidate yet:** current dirty MAATAA, NEVO, TLPS location, HKD, and platform-service worktrees; their changes may contain unique work.
- **Explicitly not duplicates:** `maataa-ui` relationship-intelligence repo vs `@maataa/ui`, NEVO Platform vs NEVO Events OS, public TLPS web vs BKT/KBM location app, and the separate AAI iOS variants.
- **Still needs product-owner intent:** whether `aai_r` should replace `aai`; whether the larger Siddham snapshot is the intended product; whether any Downloads prototype should be promoted over the selected Git source.
- **No archive/delete list yet:** exact hash comparisons of all NEVO/MAATAA packs and data/media snapshots have not been run. Candidates remain preserved.

## Safe next decisions

1. **Choose the owner/source repository per family:** MAATAA UI, NEVO Events, `tlps.in`, MOM/KBM, Brahmini/NOVA, and Siddham/ॐ.
2. **Compare candidates without moving them:** Git remotes, commit ancestry, uncommitted diffs, file manifests, package identities and unique data. For non-Git snapshots, compare file manifests and hashes; exact duplicate claims require that evidence.
3. **Create a small portfolio workspace:** after source choices, create one folder containing this catalog, project links, owner/status records and shared release/evidence pointers. Keep repositories in place initially; use symlinks or workspace/project-manager entries rather than copies.
4. **Archive only after a preservation check:** clean/commit or snapshot dirty work, check nested repos and ignored data, then archive exact duplicate copies. Do not delete candidates based only on names, dates, screenshots or similar appearance.
